# Specification: composition

Build the four model compositions from the organization's patched full model. Apply each organization patch once, then project that result. The composer also accepts Jig's own edition for a Jig-only run. The organization builds this tool from this specification and proves it with `fixtures-compose.yaml`.

## Ideal state

- **CO-1** The default run produces full, Ratchet alone, core and Jig alone from the same patched input. These are projections of one design. They are never separate patches or variants.
- **CO-2** Match complete identities. In full, Ratchet and core, Ratchet's own ids are bare. In Jig alone, Jig's own ids are bare. Other identities keep their namespace. Shared records gain `shared:` once.
- **CO-3** Load the shared layer once. Preserve shared agreement content, owner records, typed fields, exposure, names, capabilities and attached tests. Namespace conversion changes identities and references. It leaves owner records and typed field vocabulary intact.
- **CO-4** Merge the shared layer vocabulary into the selected design's layers. A lone edition's partial layer files are valid composer inputs. They are not complete model-check inputs until this merge has run.
- **CO-5** A lone build retains only incident shared crossings. Every retained absent endpoint becomes a boundary from its complete declared exposure. Missing or malformed marks refuse the entire run before output. Present endpoint marks must agree with the derived marks under MC-112.
- **CO-6** Report the known records omitted by projection. An omitted record is outside this composition. An unknown reference is still an error in the model checks.
- **CO-7** Preserve the verified full security floor in every projection. Local checks still judge local edges. A Jig-only adopter reads that annotation from its edition's shared layer.
- **CO-8** Inputs stay unchanged. Identical inputs produce identical output bytes. Build every requested result before writing any output.
- **CO-9** Every supplied unit carries an explicit numeric `phase`, an integer from 1 to 5. Missing, null, nonnumeric, fractional or out-of-range phases refuse before projection and before any output, including units a requested mode would prune. Phase claims and author metadata never substitute for this portable input field.

## Inputs

The command accepts `--model`, `--layer`, `--shared`, `--units`, `--out`, optional `--floor`, optional `--overlay` and optional `--mode all|full|ratchet|core|jig`. The default mode is all. Paths are relative to the calling directory.

`--model` names the patch applier's output model. For all, full, ratchet or core it must contain both designs. `--layer` names the patch applier's compiled layer for that same model. It holds `realization.yaml`, `quality.yaml`, `failures.yaml` and `overlay-aws.yaml`. Optional `modules.yaml` and `threat-closures.yaml` retain their existing meanings. `--shared` names the patch applier's shared output. `--units` names the corresponding unit list or composed unit mapping. Preserve organization metadata on the model.

For a fresh Jig-only run, use Jig's `model.yaml`, its folder as the layer, its `units.yaml` and its `seams.yaml`, with mode jig. No Ratchet folder is required. Shared declarations describe the absent Ratchet endpoints and agreements. The absence of that source permits no attempt to infer its implementation.

In mode jig, a model with no namespace is Jig's own input. Other modes default a missing namespace to ratchet. The overlay option names the organization's compiled overlay when it uses a file other than overlay-aws.yaml. Preserve that file's basename in each output layer. The basename follows the patch applier's overlay naming grammar. Every required model and layer document is a YAML mapping. Units is a list or a mapping with a units list. Missing or malformed required inputs refuse the run.

`--floor` names the full model checker floor report, a JSON mapping from complete contract identity to a list of rule codes. After a design change, run the model checks on the patched full composition to derive this report. Derive against current edges with previous derived `security.floor` and `security.relevant` annotations removed from a temporary checking copy. Preserve every authored raise. Require that full check to pass before relying on its floor. Supply the resulting report to the composer for all four projections. Every shared contract must have an entry. Replace its derived floor and relevance, preserving its raise. A composer never fabricates a floor by checking a lone model. Without this option it preserves the supplied shared annotations. In Jig alone those are the verified annotations in the edition's `seams.yaml`. Recheck the full composition whenever a patch changes a shared contract or a relationship that can affect its floor.

## Apply once, project afterwards

Start from the full composition in the Ratchet edition. Apply the organization's patch series with the patch applier and shared outputs enabled. Use the compiled model, layer and shared output as the composer inputs. A shared identity-binding patch and its `expects` hashes are evaluated once on this full baseline. The composer preserves that bound agreement in every mode and never replays the binding against a projected assumptions list. Keep the patch and its owner acceptance record as the evidence for every projection. MC-114 still applies before projection.

A Jig-only organization authors its patch against its Jig composition. If it later joins the full composition, migrate the patch by the upgrade rules and recompute its compare-and-set hashes against the full baseline. Do not reuse a hash of a projected list as a hash of a different list.

## Composition algorithm

1. Read all inputs. Partition the supplied full model by record identity into Ratchet, Jig and shared records. Bare ids belong to the model's `namespace`, default ratchet. Exclude boundary placeholders from implementation sources. The shared document is authoritative for shared records. Partition layer entries, scenarios and units by the same identity. Keep the complete shared document, with patched shared layer entries replacing entries of the same identity.
2. Form an identity registry for each namespace from systems, zones, elements, relationships, contracts, views, non-module seams, finding kinds, units, capabilities, planes, scenarios and runbooks. Shared capabilities have one identity. A bare shared capability in requires or provides gains `shared:`. Qualify each source's own references, then remove only the selected design's own prefix. Full uses Ratchet as its selected design. Do not prefix vocabulary values or descriptive names as if they were identities.
3. Full loads both designs and shared. Ratchet alone loads Ratchet and shared. Jig alone loads Jig and shared. Core starts from Ratchet alone and removes module elements, module relationships, relationships touching removed endpoints and module contracts. Contract producer and consumer membership in core retains present implementation endpoints. Other modes preserve the complete membership lists, including absent sides.
4. Before filtering, compare each exposure declaration with every implementation endpoint available in the input. Derive exposure through data, inference, feedback and observation relationships, stopping at structured content, as MC-7 defines. Derive model freedom and agent reachability as MC-112 defines. Require all crossing endpoints to declare `agent_reachable`, `exposed` and `model_free` as booleans, and `role_class` and `kind` as nonblank strings. Unknown endpoints in a loaded implementation are stale declarations. In a Jig-only input, declarations for the absent design supply the boundary without an implementation comparison. Seed that absent boundary's declared exposure when deriving propagation across shared edges into the present design.
5. In lone modes retain a shared crossing only if an endpoint belongs to the selected design, or both endpoints belong to shared. A shared external endpoint alone does not make a crossing incident to Jig. Core additionally applies its module pruning. For every retained endpoint absent from the implementation, add one element with the declared five marks, `boundary: true`, its complete id, its declared namespace, its name from the shared `names` map or the id, system `shared:EXT` and zone `shared:existing`. Boundary parts are context, not local implementations. Put their declarations in the model's `outside` map.
6. Emit `composition_omitted` with `elements`, `relationships`, `contracts` and `modules` lists. Compare the complete input inventory with the retained implementation inventory. Boundary endpoints remain in the omitted implementation list. Keep only known source identities in these lists. For a Jig-only input, the absent parts and contracts explicitly named by shared agreements, attached tests and seam declarations form the known absent inventory. Preserve declared outside references for contract membership, premises and attached tests. They do not become fictitious implementations.
7. Filter views and sequence steps to retained implementation members and relationships. Shared seam crossings name only retained shared relationships, with carries and point preserved. Preserve explicit organization declarations on module seams. In core, write never_cross and default_exceptions lists on every seam, including empty lists when neither key was supplied. Filter them to retained contracts and carried crossings and drop an exception whose contracts list becomes empty. Pass the original organization exception file to model checks in every mode. Core checks exclude its pruned shared contracts from that file without masking unknown contract names.
8. Merge layer maps in design order, then shared: `elements`, `contracts`, `planes`, `tiers`, `failure_modes`, `account_classes` and `zone_accounts`. Full uses Ratchet then Jig then shared. Retain entries for implementation elements and contracts present in that composition. The literal fit and account class vocabulary keeps its rule meaning, so `shared:existing` in those value fields is written as `existing`. Plane and zone identities retain their qualification. Merge failure scenarios from selected layers and the tests attached to shared contracts and assumptions. Keep a scenario unless all its named parts are omitted. Deduplicate an attached test by full scenario id when it is already in the compiled failure layer.
9. Compose units from the loaded designs. The mapping holds `namespace`, `namespaces`, `composition`, shared `capabilities`, declared `modules` and `units`. Keep each unit's own explicit numeric phase. Core drops units touching removed parts or tagged with modules, then repeatedly drops units whose required capabilities have no remaining provider. Other lone modes keep external capability declarations for the unit graph to report as waits. Merge shared vocabulary even when a design's layer has no vocabulary map of its own.

Critical paths in the supplied compiled quality layer belong to that input design's namespace. Keep them with that design's layer. Do not copy Ratchet's critical path requirements into the Jig-only layer. Preserve the patch applier's before and after layer semantics for an organization change.

## Outputs and refusals

Under the output folder, write one folder per requested mode. Each holds `model.yaml` and a `layer/` folder with `realization.yaml`, `quality.yaml`, `failures.yaml`, the selected overlay file, `units.yaml`, `threat-closures.yaml` and `seams.yaml`. Include modules.yaml when the input supplied that optional declaration. Its absence keeps the model checker's existing modules-absent behavior. The shared file belongs inside the layer folder consumed by the checks. It remains the complete patched shared document, including crossings omitted from a lone model. Set the model's `namespace` and `composition` for that mode.

Serialize deterministic YAML with input record order preserved within each source and namespace order as above. Exit 0 after writing all outputs. Invalid command options report `compose.options`. Missing or malformed inputs report `compose.input`. A missing or invalid unit phase reports `compose.stage`. A missing full floor entry reports `compose.floor`. Exposure refusal reports `composition-exposure-missing` or `composition-exposure-stale`. A shared agreement with writers in multiple namespaces reports `shared-writing-side`. Refusals exit 2 and write no result files. Ordinary design verdicts remain the model checker's responsibility.

Run the model checks on every output model with that output's layer folder and the same organization exception file. A successful composition alone is not a passing design check.

A projected shared contract's derived annotation is `security: {raised: <authored raise>, floor: [<rule code>], relevant: <boolean>}`. Omit `raised` when none was authored. An empty floor with no authored raise sets `relevant: false`. These annotations belong to the projected model. The emitted shared document retains its supplied annotations. Missing entries in a readable floor mapping, including an empty mapping, are `compose.floor`.

Determinism compares repeated runs on the same inputs. A Jig-only run from partial layers and a Jig projection from a full input need not serialize layer keys in the same order. Compare their layer mappings as parsed documents where the fixtures supply a reference from a different input layout.

## Acceptance fixtures

`fixtures-compose.yaml` uses the self-contained sources in `fixtures-model-inputs.yaml`. Its `fixtures` list accepts `name`, `base`, `modes`, `patch`, `bind_identity`, `remove_mark`, `floor`, `custom_overlay`, `error`, `rule`, `without_checker`, `scenario` and `unit_stage`. `unit_stage` changes the first input unit's phase to the supplied value, or removes it for `missing`; require the stated refusal in every requested mode without outputs. An unknown key fails the runner. Base full starts from the supplied `compositions.full` documents, as described below. Base jig uses the supplied Jig source model and partial layers with the same shared document. Modes is the list of results requested. Floor supplies the exact full floor report and requires its annotations on every retained shared contract. An empty floor mapping refuses. Custom_overlay uses the same overlay content under overlay-local.yaml and requires that output name without an extra overlay-aws.yaml.

Patch supplies an ops mapping. Apply those exact ops once with patch id `O01` through the patch applier before projection. Pass the shared document and compiled layer into that application. Use its model, shared output and compiled layer as composer inputs. Require jig:org.adopter-probe and shared:o01-probe in full, the projected part and crossing in Jig alone, and a boundary in Ratchet alone. Core omits their module. `bind_identity: true` modifies shared:ext.engineering-workflows. Copy its assumptions and bind every owner of the first assumption that has owners to the identity org-team: followed by that owner's role. Set each newly assigned identity basis to confirmed, hash the original assumptions field for expects and supply acceptance from every newly bound identity. Apply that one operation once. Require those same identities after every projection. `remove_mark` deletes that mark from the first row in the first namespace of the first shared seam's exposure mapping and requires the stated refusal with no outputs.

For base full, the supplied compositions.full documents are the complete starting model and layers. The sources entry shared/seams.yaml is the complete shared input. For base jig, use the supplied Jig source model, partial layers and unit list with that same shared input. When base jig supplies floor, attach its exact floor and derived relevance to the shared contracts before invoking the tool without the floor option. This models the annotations shipped in Jig's own shared layer. A full case with floor passes it as the floor option.

The binding operation is `modify_element` on `shared:ext.engineering-workflows`, with the copied list in `set.assumptions` and its PA-22 pre-op hash in `expects.assumptions`. Supply one acceptance for each distinct newly bound identity. The root shared copy retains its root-form references and receives the changed owner rows. Export a patched shared crossing with a bare shared id and namespaced design endpoints. Store an endpoint declaration under `exposure.<namespace>` with its complete part id.

Each case runs twice, compares result bytes, asserts unchanged input documents, and checks retained crossing ids, boundary marks, omitted lists, merged vocabulary, scenarios and shared placement against the reference namespace composition. The patched case also requires its new part's realization and overlay entries. Composer acceptance requires no model checker. The partial-layer case checks vocabulary and the supplied floor annotations as data. A separate integration check runs the model checks on those outputs. A missing checker leaves that integration unchecked and does not fail a composer fixture. The suite proves the composer from portable inputs, without an author source tree.

## Exact projection contracts

The following numbered contracts settle the projection details. The fixture's `rule` selects the corresponding assertion against the supplied portable reference documents. It is fixture setup, never a tool option. `without_checker: true` requires that case to run with no checker imported, discovered or invoked. A runner must support it. Ordinary composer assertions still run.

| Rule | Required behavior |
|---|---|
| 1 | Registry ids include systems, zones, elements, relationships, contracts, views, non-module seams, finding kinds, units, capabilities, planes, scenarios and runbooks. Rewrite reference values and identity map keys only when they match registry ids or explicit qualified references. A complete registered identity used as a descriptive scalar is projected too. Reference fields include id, name, from, to, parent, system, trust_zone, plane, produced_by, consumed_by, carries, by, judged_by, fallback_by, relied_on_by, stop_gate_compensated_by, part, parts, elements, relationships, contracts, contract, claim, requires, provides, measured_by, rests_on, never_cross, verified_from, seam, view, runbook, accepted_by, owner_role and until. A milestone until is a string reference. A calendar date remains a date. Rewrite map keys in elements, contracts, planes, names, outside and known zone_accounts keys. Owner and typed fields subtrees are unchanged. Role class, kind, level, fit, account, class, content, module, point and between are vocabulary. |
| 2 | Scenario ids and runbooks belong to their source namespace. A claim reference already qualified keeps its identity. An unregistered bare claim reference stays bare. |
| 3 | Module seam ids and their between values are module vocabulary. Derive module seams from current interface points before projection pruning. Keep their declarations in each mode. A core seam may still name a known omitted relationship. The checker prunes those references through the omission inventory before judging interfaces. A lone seam without an implementation on its module side has no derived crossings. Preserve explicit organization crossing declarations only when their relationship remains. |
| 4 | Rebuild shared seam crossings from retained shared relationships crossing namespace sides, in shared document order. This includes shared relationships absent from the input seam's crossing list. Carries comes from the relationship. Preserve a seam declaration's point when present, otherwise the relationship's point. This is composition of whole shared crossings under MC-113. It grants no module-seam declaration. |
| 5 | Core removes every module-tagged element, relationship and contract and every relationship touching a removed endpoint, including endpoints in the absent creation design. Core creates no boundary for a removed module endpoint. |
| 6 | outside_references is a distinct list in first-occurrence order. Visit shared contracts' produced_by then consumed_by lists, shared assumptions' relied_on_by then fallback_by, seam never_cross, then attached scenario elements, contracts before assumptions. Keep only identities known in the source inventory. Shared identities may occur. This list records declared context, never implementation. |
| 7 | Create boundaries in first encounter order over retained crossings, from before to. Copy the exposure row including part, then add id, namespace, boundary true, name, system shared:EXT and trust_zone shared:existing. outside maps each id to the exposure row plus id and namespace. Boundary parts are omitted implementations and remain in the omitted element inventory. |
| 8 | Views keep implementation members and retained relationships. A boundary is not a view implementation member. Sequence steps keep their selected source's retained endpoints. Jig alone has an empty sequence. |
| 9 | composition_omitted.modules visits module tags on complete source elements in input order, deduplicates them and excludes any module with a retained implementation element. |
| 10 | Record order is Ratchet, then Jig, then shared, restricted to loaded designs. Within each source preserve input order. Shared document records replace shared copies in the model. Append boundaries last. Preserve the selected design's other top-level metadata. |
| 11 | Write fit and account values shared:existing as literal existing in the composed overlay. They are vocabulary values. Keep account-class descriptions and zone-account value lists intact. A zone_accounts key is qualified only when the registry identifies that zone. A bare key naming no loaded zone remains an unused declaration. It does not become a Jig zone or a known reference. |
| 12 | Failure scenario order is selected design layers, then patched shared scenarios from the input layer, then shared layer scenarios, then tests attached to shared contracts, then tests attached to shared assumptions. Keep the first full id when deduplicating. Keep a scenario with no elements or with any retained element. Omit only a non-empty element list whose members are all known omitted parts. Boundary parts count as omitted implementations for this test. Mixed scenarios remain whole. Organization scenarios use the same projection rules. |
| 13 | Threat closures are selected design closures, then shared closures. Patched input-layer shared entries replace matching shared document entries. Core keeps closure records even when they cover no retained cell. |
| 14 | Core drops module units and units naming removed parts, then repeatedly drops units with requirements no remaining unit provides. Preserve survivor order. No external declaration supplies a core provider during this pruning. |
| 15 | Emit finding_kinds only when at least one selected design supplies a kind record. Omit the key when every selected registry is empty or absent. The model checks distinguish an empty present registry from an absent registry, so the composer removes the empty key. |
| 16 | Derive exposed through MC-7 over loaded and shared relationships, seeded by untrusted targets and declared exposed absent boundaries. Structured content stops propagation. Derive model freedom by MC-86 with the model-path list in the model-check specification. Agent reachability is agent_reachable true. Compare role_class and kind as declared. Compare only implementations supplied in the input. |
| 17 | Before any mode filters, validate every shared seam exposure row and require a declaration for every shared crossing endpoint. All five marks must be well formed, including nonblank role_class and kind. A missing or invalid mark refuses every requested output. |
| 18 | Refusals exit 2, write no result files and emit JSON on standard error with error equal to the refusal code and message explaining it. |
| 19 | With a floor report, every shared contract security record keeps its authored raise, takes the exact report floor list, and sets relevant when that list is non-empty or a raise exists. The emitted layer seams.yaml remains the complete supplied shared document. A report does not restamp that input document. |
| 20 | Floor keys are complete identities. Match shared: followed by a root shared contract's bare name, including when attaching the verified floor for a Jig-only input. |
| 21 | Fixture patch ops are applied once before composition. The patched model, compiled layer and shared output are the inputs. Preserve patch, patch_op and patches provenance on model and shared records. Preserve the added part's realization and overlay entries. |
| 22 | The binding fixture copies the first shared engineering assumption with owners, sets each identity to org-team: followed by its role with basis confirmed, hashes the entire pre-op assumptions list and supplies each new identity's acceptance. Apply once to the full baseline and retain that same agreement in each projection. A basis marker, when supplied, also survives unchanged. |
| 23 | Keep omission lists as they are. A full input supplies the complete known inventory. A Jig-only input knows absent records only through shared contracts, premises, attached tests, crossings, exposure and never_cross declarations. Compare its omitted lists as known subsets of the supplied full-source reference and require every boundary. Do not fabricate the absent design's complete inventory. Unit modules come from supplied modules.yaml, otherwise from the input unit mapping, otherwise from loaded element module tags. Module ids are vocabulary. A Jig-only fixture cannot demand module declarations absent from its inputs. |
| 24 | Require an explicit numeric phase from 1 to 5 on every portable unit before filtering. Preserve that number in each retained unit even when phase claims disagree. Missing and invalid numbers refuse with compose.stage, exit 2 and no output. |

Each rule fixture asserts the named fields independently of integration checks. The fixture runner must not substitute a model-check pass for these data assertions. The partial-layer fixture without a checker also checks all five exposure marks, the complete output file set, owner and typed-field preservation, merged vocabulary, incident crossings, scenario ids and floor annotations.

Compare rule assertions with the supplied compositions documents, never with a second invocation of the composer being tested. A fixture may also supply `scenario`, the stable id of an organization scenario added by its patch. Require that scenario, its matching runbook, test and patch provenance in full, Ratchet and core, and its omission from Jig when the scenario belongs to Ratchet. The part-and-crossing assertions for patch fixtures apply when their ops add the named probe part. A scenario-only patch creates no such part.
