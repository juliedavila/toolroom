# Reference R0: Building blocks, with their settings and their wiring

*Ratchet: closed-loop security validation for AI-assisted engineering. Reference R0. Edition 5.1.3, Thesis 1.4.3, 2026-10-31, build 694de224+local.*

A builder starts here. Ratchet is built block by block: each plane of the core is one block, and each optional module is one block. Every part sits in exactly one block, and the build checks it. Each row joins what the other reference parts hold about that block: its parts (R2), the trade-off cards whose rules it carries (R1), the profile fields and dials an organization sets for it (R7 and R3), the contracts that cross its edge (R2), where an existing tool or a swap point serves first, what switches it on, the phases and work units that build it (R4), and its AWS candidates (R5).

Every field is generated from the design model, so a design change moves this index with it. A block's rule cards are those whose failure scenarios exercise one of its parts, plus, for a module, the four rules it inherits and the cards that enforce its separations. Its profile fields are the build-or-buy entry keyed by its plane or its parts, the existing tool at each step of the loop whose units build its parts, the separation fields its cards check, and a module's own switch-on fields. Its dials are those named in the failure scenarios on its parts or in its cards' conditions.
